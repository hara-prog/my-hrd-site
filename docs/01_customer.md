## 3行の評価

2行目（困りごと）が一番弱いところです。「発行漏れ・記入ミス・重複入力」という**具体的な作業**は書けていますが、「月に何件」「1件何分」という**頻度・時間**が入っていません。ここが無いと画面の項目や優先度が決めきれないため、今回は業種から自然な数字を仮に置いて 🔮 を付けて進めます。

## 今回のスコープの絞り込み

このお題は「講師依頼書の発行」まで含みますが、書類のPDF自動生成やクライアント側からの入力は今回は作りません。**「講師依頼データ」を1件ずつ登録し、検索・絞り込みし、ステータス（未依頼→依頼済み→確定→実施済みなど）を変える一覧管理ツール**に絞ります。書類発行や見積書生成は、データが一元化された後の次のステップだからです。

## 解く課題

- **困っていること**: 講師への依頼書発行が漏れたり記入ミスが起きる。見積書やメモに同じ情報（講師名・クライアント・研修テーマ・日時・場所・講師料など）を何度も入力し直している。情報が一気に揃わず段階的に入ってくるため、一元管理ができておらず、依頼書を発行する段になって過去のやり取りを見返す羽目になる。
- **今その人はどうやっているか**: 🔮 Excelや紙のメモ、メールやチャットのやり取りを都度見返して、講師ごと・案件ごとに情報をかき集めていると思われる。
  → 確かめ方: 「今、講師への依頼内容はどこにメモしていますか？（Excel・紙・メール検索など）」
- **かかっている時間 / 費用**: 🔮 依頼書1件を発行するための情報確認・転記に30〜60分、月10件前後の依頼があるとすると月5〜10時間程度。記入ミスによる講師との行き違いの対応にさらに月1〜2時間かかっていると思われる。
  → 確かめ方: 「依頼書を1件作るのに、情報を集めるところから含めてだいたい何分かかりますか？月に何件くらい依頼を出しますか？」
- **なぜ今まで誰も解決していないのか**:
  - [x] データが散っている　[ ] 市場が小さい　[ ] 量が多すぎる
  - [ ] 判断が非定型　[ ] n=1すぎる
  - 🔮 情報が電話・メール・打ち合わせなど複数のチャネルから段階的に入ってくるため、汎用のExcelテンプレートや顧客管理ソフトでは受け止めきれず、各社が自己流の運用になりがちだと思われる。
    → 確かめ方: 「今の管理方法で一番困っているのは、情報がバラバラなことですか？量が多いことですか？」
- **このサイトで最初に成立させたいこと（1つだけ）**: 講師依頼1件ごとの情報（講師・クライアント・テーマ・日時・場所・講師料・集合時間など）を1画面の一覧で登録・検索・ステータス変更できること。

## 出口 ── 作る前に確認する3つ

### ① 誰が払うか

- **払う人**: 🔮 研修会社の経営者本人（原社長）。事務スタッフが使う場合も、費用の決裁は社長が行うと思われる。
- **その相手は、この種のものに金を出す商習慣があるか**: 🔮 法人向けの業務効率化ツール・スケジュール管理ツールに一定の予算を割く商習慣はあると思われるが、金額感（月額いくらまでなら払うか）は未確認。
  → 確かめ方: 「こういう管理ツールがあったら、会社として費用を払って導入する対象になりますか？月にいくらくらいまでなら払えますか？」

### ② どう届くか

- **その市場が「実際に使っている」経路**: 🔮 下の経路（紹介・口コミ・業界内の直接接触）が中心だと思われる。企業研修業界は比較的狭く、経営者同士のつながりや研修会社の勉強会・協会での紹介で情報が回るのではないか。「講師依頼 管理ツール」のような検索ボリュームは小さいと予想される。
  → 確かめ方: 「同業の研修会社さんとの横のつながりはありますか？そこで業務効率化の話をすることはありますか？」

> ⚠ ②はまだ 🔮（仮説）です。ここが外れると量では取り返せないため、最優先で確かめてください。

### ③ 受け取れるか（決済・審査・規制）

- **確認したか**: いいえ
- **確認した内容**: 🔮 投資・金融／医療・健康／法律相談などの要審査業種には該当しない、通常の法人向け業務ツール（月額課金）で問題ないと思われる。ただし正式な確認はまだしていない。

### 競合には必ず「DIY」を入れる

- **既存の競合**: 🔮 Excel／スプレッドシート、Notionなどの汎用管理ツール、名刺管理・CRMツールの流用。研修会社専用の業務システムがあれば、それも競合になりうる。
- **DIY競合**（顧客が自分でAIに作らせる）: 🔮 原社長自身がChatGPTやClaudeに「講師依頼の管理表を作って」と頼み、Excel/Notionのテンプレートを自作するケース。
- **選ばれる理由**: 🔮 「時間」──汎用ツールは項目設計・入力フォームを自分でゼロから組み立てる必要があるが、このツールは「講師依頼書に必要な項目」が最初から揃っているため、導入初日から情報を探す時間が減る。

## やらないこと

- 依頼書・見積書のPDFなど書類の自動発行機能は作らない（今回はデータの一覧管理まで。書類発行は次回以降）
- 講師本人がログインして自分の予定や空き状況を入力する機能は作らない（お客さん側からの入力は第2〜3回で扱う）
- クライアント（研修依頼主）向けの提案・マッチング機能は作らない（社内の講師依頼データ管理だけに絞る）

## 🔮 次回までに確かめること

1. **② どう届くか（下の経路が本当に使われているか）** → 誰に聞くか：原社長 → 質問：「同業の研修会社さんとの横のつながりはありますか？そこで業務効率化の話をすることはありますか？」
2. **かかっている時間・費用** → 誰に聞くか：原社長 → 質問：「依頼書を1件作るのに、情報を集めるところから含めてだいたい何分かかりますか？月に何件くらい依頼を出しますか？」
3. **① 誰が払うか（金額感）** → 誰に聞くか：原社長 → 質問：「こういう管理ツールがあったら、会社として費用を払って導入する対象になりますか？月にいくらくらいまでなら払えますか？」

このうち ② どう届くか だけは、量では取り返せません。最優先で確かめてください。
